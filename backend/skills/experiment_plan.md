### 技能目标

把用户的研究想法转化为一份**能直接照着执行**的实验方案，明确每一步跑什么、
和谁比、看哪个指标、需要多少算力、失败时怎么办。

### 执行步骤

**第 1 步 · 补齐关键信息**
先判断用户是否给出了：任务类型、数据集、现有 baseline、算力条件。
如果缺失**算力条件**或**数据集**，在方案开头用一行「待确认」列出，然后按最常见情形给出默认假设
（如「按单卡 24GB 显存、数据集沿用公开基准」），继续输出方案，不要停下来反复追问。

**第 2 步 · 检索领域依据**
调用 `cv_rag_search` 检索与该任务相关的方法选型、评价指标与调参经验（一次即可）。
涉及算力可行性时可调用 `gpu_status` 查看本机 GPU。

**第 3 步 · 输出方案**

严格按以下七节输出：

#### 一、任务定义与评价指标
- 输入输出是什么，属于分类 / 检测 / 分割 / 其他。
- 主指标是什么，为什么选它；辅指标是什么。
- **明确指标的陷阱**：类别不平衡时像素准确率会失真，检测只报 mAP50 会掩盖定位问题。

#### 二、数据集与划分
- 用哪个公开数据集或自建数据集，规模量级。
- 训练 / 验证 / 测试划分比例，是否与已有工作对齐以保证可比性。
- 数据预处理与增强策略（几何增强需同步变换标注）。

#### 三、基线选择
- 至少 3 条基线：经典方法、当前主流方法、与本文最接近的方法。
- 每条基线注明：是否用官方代码、是否加载预训练权重。
- **必须说明基线复现的预期差距**，以及对齐不上时怎么处理。

#### 四、主实验
- 实验矩阵：每行一个配置，每列一个指标。
- 训练预算统一（epoch 数、分辨率、增强策略一致），否则对比无效。

#### 五、消融实验
- 每个待验证组件单独开关，做到**单一变量**。
- 给出消融表格的表头设计。
- 至少包含：去掉某模块、替换某模块、改变关键超参三个维度。

#### 六、算力预算与时间估算
- 单次训练预计耗时、总实验次数、总 GPU 小时。
- 如果预算紧张，明确给出**优先级排序**：哪些实验必须做，哪些可以砍。

#### 七、风险与备选方案
- 每个主要风险配一条备选路径（如「若主方法在小目标上掉点，则提高输入分辨率并增加 P2 层输出」）。
- 指出最可能失败的环节和提前验证的方法。

### 硬性约束

- 使用简体中文，方法名与指标名保留英文（mAP50-95、mIoU、Dice）。
- 方案必须包含具体的数值建议（学习率、batch size、epoch 数），不能只说「适当调整」。
- 消融实验部分必须强调随机种子与多次运行，单次结果不足以支撑结论。
- 总长度 800~1400 字。
